# دستور دورة المستندات والمحاسبة — تطبيق النظام الكامل

## نطاق المراجعة

تمت مراجعة الوحدات الفعلية للمحاسبة والفواتير والمعاملات والمبيعات والمشتريات والعملاء والموردين والخزينة والبنوك والقيود والعملات والفترات والحج والعمرة والحجوزات والتقارير والحذف الآمن والصلاحيات والأرشفة وسجل النشاط وخادم الحفظ.

## البنية الحالية المعتمدة

- `src/accounting/engine.ts`: القيود والترحيل والعكس والاتزان والربط بالمصدر.
- `src/accounting/invoices.ts`: دورة الفاتورة والإشعارات والضريبة والأرصدة والإلغاء.
- `src/accounting/transactions.ts`: القبض والصرف والمصروفات والتحويلات والحجوزات والخدمات.
- `src/accounting/currency-periods.ts`: العملات والفترات والإغلاق وإعادة الفتح.
- `src/core/delete-center.ts`: الحذف الآمن الموحد في الواجهة.
- `src/core/umrah/*`: دورة برامج وحجوزات وخدمات ومشتريات الحج والعمرة.
- `server/src/authz.ts`: خط الدفاع النهائي للصلاحيات ودورة الحياة وعدم قابلية تعديل المستند المالي.
- `server/src/server.ts`: الحفظ الذري، التزامن، سجل المراجعة والاحتفاظ.

## القواعد الموجودة التي تم الإبقاء عليها

- قيد غير متوازن لا يرحل.
- الفواتير والسندات والمصروفات والقيود المرحلة تعالج بالعكس أو الإلغاء وليس الحذف.
- أسباب الإلغاء والعكس وإعادة فتح السنة إلزامية في الإجراءات الحساسة.
- الفاتورة المرتبطة بتحصيل أو إشعار لا تلغى قبل معالجة التابع.
- الحجز أو البرنامج المرتبط بمعاملات مالية لا يحذف.
- أوامر الشراء المعتمدة/المستلمة/المحولة لا تحذف.
- العملاء والموردون والمندوبون يُعلقون أولًا، والحذف للغير مستخدم فقط.
- العمليات المركبة الأساسية تستخدم `DB.atomic` في الواجهة وTransaction + row lock في الخادم.
- Idempotency موجود لربط أحداث الحج والعمرة ومنع تكرار الفاتورة/القيد.
- الفترات والعملات تحتفظ بسعر الصرف التاريخي وتمنع الترحيل في الفترة المغلقة.
- الحالات والألوان تعتمد على `StatusCatalog` المركزي.

## فجوات P0 التي تم إغلاقها

1. **الحذف المرتبط من طلب مباشر للخادم:** أضيف فحص مركزي يمنع حذف عميل أو مورد أو مندوب أو حساب أو مركز تكلفة أو خزنة أو عملة أو ضريبة إذا استُخدم تاريخيًا.
2. **حذف مسودة لها توابع:** أضيف منع لحذف فاتورة مسودة إذا وُجد مستند أو قيد أو تحصيل أو سداد أو إشعار مرتبط بها.
3. **مراجع المبيعات والمشتريات:** أضيف منع خادم لحذف عرض سعر أو أمر شراء أو برنامج أو حجز إذا وُجدت مستندات لاحقة.
4. **تعديل المستند بعد الإلغاء:** أصبحت السندات والمصروفات والإشعارات والتحويلات وأوامر الشراء وعروض الأسعار والحجوزات والبرامج الملغاة/المرحلة غير قابلة لتعديل الحقول المالية حتى بعد تغير الحالة من `posted` إلى `void/cancelled/reversed`.
5. **سجل المراجعة:** تنظيف سجل النشاط أصبح يحذف النشاط التقني فقط. أحداث الحسابات والقيود والفواتير والسندات والمشتريات والعمرة والفترات والصلاحيات والإعدادات تبقى محفوظة ولا يشملها تنظيف History.
6. **اتصال Android:** فصل انقطاع شبكة الجهاز عن تأخر الخادم، والتحقق الفعلي قبل عرض «وضع غير متصل».
7. **التنقل داخل الأقسام:** تثبيت تمرير مسار الوحدة قبل حدث الضغط، ومنع رجوع زر «الفواتير» أو أي زر جانبي إلى الصفحة الرئيسية بدل فتح الوحدة المطلوبة.

## مصفوفة دورة الحياة المعتمدة

| الحالة | تعديل مالي | حذف | الإجراء الصحيح |
|---|---:|---:|---|
| مسودة بلا توابع | مسموح | مسموح | حفظ / اعتماد / حذف |
| معتمد بلا تنفيذ لاحق | مقيد | ممنوع | إلغاء اعتماد حسب الصلاحية أو إلغاء |
| منفذ جزئيًا | ممنوع للجزء المنفذ | ممنوع | استكمال أو إغلاق/إلغاء المتبقي |
| منفذ/مرحل | ممنوع | ممنوع | عكس أو مستند تصحيحي |
| مغلق | قراءة فقط | ممنوع | عرض وطباعة ومراجعة الروابط |
| ملغى | قراءة فقط ماليًا | ممنوع إذا له تاريخ | عرض السبب أو إنشاء نسخة جديدة |
| معكوس | قراءة فقط بالكامل | ممنوع | عرض القيد الأصلي والعكسي |

## الاختبارات الدائمة المضافة

أضيف `accounting-constitution-smoke.mjs` إلى مسار التحقق الرسمي، ويمنع رجوع الفجوات التالية:

- حذف عميل مستخدم.
- حذف حساب عليه قيد.
- حذف فاتورة مسودة لها مستند تابع.
- تعديل سند قبض ملغى.
- تعديل حجز حج/عمرة ملغى.
- حذف سجل المراجعة المالي ضمن تنظيف النشاط التقني.
- فتح المسار المحدد من القائمة الجانبية وعدم الرجوع إلى لوحة البداية؛ ويغطيه `workspace-navigation-smoke.mjs`.

هذا الملف وقواعده مرجع إلزامي لأي ميزة جديدة: لا حذف لأثر تابع، ولا تعديل مالي بعد الترحيل، والتصحيح بالعكس أو الإلغاء أو مستند تصحيحي مع الحفاظ على التاريخ والروابط.
