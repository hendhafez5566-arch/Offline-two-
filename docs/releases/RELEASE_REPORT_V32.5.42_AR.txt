ELHAFEZ TOURISM — RELEASE REPORT v32.5.42
========================================
النسخة الأساسية: v32.5.41 CUSTOMER-SYNC-RELIABILITY-FIX
الإصدار الجديد: v32.5.42 CUSTOMER-WHATSAPP-PDF-SHARE
Database Migration: غير مطلوبة (migrationRequired=false)

الهدف
-----
إضافة مشاركة أي مستند مطبوع مرتبط بطرف واحد معروف إلى صاحبه عبر واتساب، من نفس طبقة الطباعة المركزية وبأقل تعديل ممكن، بدون إعادة بناء الشاشات أو تكرار وظائف PDF/Print.

ما تم تنفيذه
------------
1) إضافة زر "إرسال واتساب" داخل نافذة الطباعة المركزية.
2) تحديد المستلم تلقائيًا من Context المستند ورقم WhatsApp/Phone المسجل، مع استخدام نفس normalizeWhatsApp الموجود في النظام.
3) Android:
   - NativePrint.sharePdf يستقبل نفس HTML المستخدم للطباعة.
   - إنشاء PDF عبر WebView PrintDocumentAdapter داخل Cache التطبيق.
   - مشاركة PDF عبر FileProvider إلى WhatsApp ثم WhatsApp Business ثم Share Chooser كـfallback.
4) Web/Laptop:
   - فتح محادثة WhatsApp على رقم المستلم برسالة جاهزة.
   - تشغيل مسار Print / Save PDF الحالي كـfallback؛ المتصفح لا يُفترض أنه يستطيع إرفاق PDF تلقائيًا دون Native/API إضافي.
5) الزر لا يظهر للتقارير العامة أو متعددة الأطراف حتى لا يتم تخمين مستلم خاطئ.
6) ربط الزر بالـUI Delegation المركزي عبر data-print-whatsapp؛ لم تتم إضافة inline event جديد للخاصية.

المطبوعات ذات المستلم التلقائي الحالي
-------------------------------------
- فواتير العملاء والموردين.
- الإشعارات الدائنة/المدينة المرتبطة بطرف.
- سندات القبض والصرف المرتبطة بعميل/مورد/مندوب.
- عروض الأسعار.
- أوامر الشراء (المورد).
- كشوف حساب العملاء والموردين والمندوبين.
- قائمة مسافري الحجز التقليدي المرتبطة بالعميل.
- تأكيد حجز الحج/العمرة المرتبط بالعميل.
- أي Module Print يمرر partyType + partyId أو Context مدعوم للطبقة المركزية.

المطبوعات التي لا يتم تخمين مستلم لها
-------------------------------------
- القيود الداخلية، المصروفات الداخلية، التحويلات بين الخزن.
- ميزان المراجعة والتقارير العامة.
- مطبوعات البرنامج الجماعية/متعددة الأطراف عندما لا يوجد طرف واحد واضح.
السبب: منع إرسال مستند لشخص/شركة غير صحيحة.
