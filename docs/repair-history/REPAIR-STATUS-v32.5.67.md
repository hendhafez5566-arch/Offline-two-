الإصدار: **32.5.67**. تاريخ التحقق: 2026-10-06.

تم تنفيذ إصلاحات الكود للبنود الـ48 في التقرير التراكمي، على نسخة كاملة من `Elhafez-Tourism-Offline-PART7-merged.zip`. بقيت الوظائف والملفات الأصلية؛ لم تُحذف وظيفة ولم يُعاد إنشاء النظام من الصفر. الإصلاحات داخل المسارات الأصلية، مع وحدة استعادة معاملات واحدة جديدة، لا طبقة تجاوز للدوال المالية.

هذا تقرير إصلاح للكود والسيناريوهات المحددة، وليس شهادة بأن جميع اختبارات المشروع ناجحة أو أن بيانات تشغيل قديمة صُححت تلقائيًا. الفشل المتبقي وحدود الإثبات موضحة صراحة أدناه.

## القرارات المحاسبية والتنفيذية

- محرك القيود يرفض الفرق الحقيقي حتى لو كان 0.01؛ تصحيح التقريب محصور في تحويل قيد متزن قبل التقريب. فروق العملة في التسويات أطراف صريحة.
- سعر الوثيقة وقيمتها الأساسية تُحفظ عند الترحيل؛ إقفال الذمم والخزائن والالتزامات يستعمل القيمة الدفترية الفعلية. الإشعارات تحفظ توزيع الصافي والضريبة لكل بند.
- الفشل المالي أو التشغيلي يعيد البيانات قبل العملية، مع الحفاظ على مراجع السجلات الموجودة. العمليات المالية المركبة والعكس تعمل داخل معاملات.
- الطرف الموقوف لا يقبل فاتورة جديدة؛ يُسمح بإقفال التزام قديم. هذا تطبيق سياسة للبند المشروط F02-03، وليس حذفًا لتاريخه أو منعًا لتحصيله.
- السند السابق لتاريخ الفاتورة يسجل مقدمًا؛ تسويته بتاريخ الفاتورة. التخصيص المباشر قبل تاريخها يرفض.
- تغيير إصدار التطبيق وتحديث ملفات PWA ونسخة الويب المدمجة في Android يمنع استمرار تحميل كود الإصدار السابق. مفاتيح تخزين بيانات الشركة لم تتغير.

## الاختبارات والأدلة

البناء الكامل `npm run build` نجح، بما فيه TypeScript للواجهة والخادم. فحص الوحدات نجح: 168 وحدة، صفر دورات اعتماد، صفر وحدات يتيمة، صفر تقييمات مكررة. أُضيفت وحدة `state-rollback.ts` إلى سجل ترتيب الوحدات صراحة، دون تعديل قواعد الفحص أو تجاهلها.

`types:ratchet` نجح دون تغيير خط أساسه: لم تُضف suppressions. المشروع ما زال يحتوي أخطاء عند تفعيل أوضاع TypeScript الصارمة غير المفعلة أصلًا؛ نجاح ratchet يعني عدم تدهور الحدود المسجلة، وليس اختفاء كل دين تقني.

## ما لم يُثبت أو لم يُنفذ

- لم تُستعمل قاعدة بيانات الشركة الفعلية، ولم تُعدّل بياناتها. القيود القديمة الخاطئة ليست محل إعادة كتابة تلقائية؛ تحتاج قيود تصحيح موثقة ومراجعة أرصدة على نسخة من بيانات التشغيل.
- الوثائق القديمة التي لا تحمل سعرًا مثبتًا قد تحتاج استرجاع السعر من قيد المصدر. بعض مسارات التوافق القديم تحتفظ بالرجوع إلى جدول السعر عند غياب اللقطة؛ لا يمكن ضمان استعادة سعر مفقود من بيانات لم تُرفق.
- الخادم اجتاز البناء، لكن لم يُشغَّل تكامل PostgreSQL وخادم مستضاف حي. الاستعادة المحلية اجتازت اختبار تخزين وفشل حقيقي؛ الاستعادة بين الخادم والمرفقات ليست معاملة موزعة مثبتة بهذا الاختبار.
- نُسخت أصول الويب الجديدة إلى مشروع Android ونجح اختبار تطابقها؛ لم يُبنَ APK/AAB ولم يُجرَّب جهاز Android فعلي.
- أداء أخذ لقطة تراجع كاملة مع قاعدة إنتاج كبيرة يحتاج قياسًا. لم يُستبدل بضمان ضعيف أو تعطيل التراجع.
- لم يُشغّل عملاؤك الحقيقيون جميع مسارات النظام من طرف إلى طرف. لا توجد مطالبة بجاهزية إنتاج شاملة قبل معالجة الفشل المتبقي وتجربة نسخة بيانات الشركة.

## إعادة التحقق والاستخدام

ZIP يحتوي المشروع كاملًا مع المصدر، build الواجهة والخادم، أصول Android المحدثة، اختبارات المصدر الأصلية، اختبارات الفحص الإضافية، وهذا التقرير والأدلة. يستثني node_modules فقط؛ تثبت عبر القفل.

```bash
npm ci
npm run build
npm run module:check
npm run types:ratchet
npm run test:repairs
npm run test:audit-repairs
npm run test:all-node-smokes
npm run test:browser-smokes
npm run test:persistence
```

اختبارات المتصفح تحتاج Python Playwright وChromium. يمكن تحديد `CHROMIUM_PATH` إن لم يكن في PATH. أدوات المتصفح المستخدمة للاختبار ليست ضمن ZIP.

`test:audit-repairs` يقرأ JSON نفسه ولا يعتبر exit 0 دليل نجاح؛ يعيد exit 1 عند أي FAIL، بما في ذلك حالة F03 القديمة الموثقة. لا يتجاهلها ولا يعيد تسميتها PASS.

تشغيل النسخة المجمعة: افتح المشروع محليًا عبر `npm run preview` ثم افتح عنوان المعاينة الذي يطبعه. للاستخدام المعتمد على الخادم، اتبع تعليمات المشروع الأصلية؛ هذه الجولة لم تثبت نشر خادم الإنتاج. احتفظ بنسخة خارجية من بيانات الشركة قبل تجربة إصدار جديد.
