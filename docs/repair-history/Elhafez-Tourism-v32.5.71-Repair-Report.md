# تسليم إصلاح Elhafez Tourism Offline — v32.5.71

التاريخ: 2026-10-08. الأساس: ZIP الكامل v32.5.70 والتقرير التراكمي F11–F18، وقد قُرئ كاملًا. **هذه نسخة إصلاح غير معتمدة للإنتاج**: السبب التاريخي لفقد البيانات F15-01 وعائق المرفق القديم F17 لم يُحسما.

## حدود الدليل

نفذت الاختبارات على شركة وهمية في Chromium وIndexedDB فعليين. إعداد بيانات البداية معلن داخل السكربتات؛ معاملات القبول نفسها نُفذت بأزرار ونماذج الواجهة، مع حساب مستقل من القيود الخام باستخدام Decimal، ومقارنة البيانات بعد إعادة التحميل. الاختبارات الإضافية التي تستدعي دوال الأعمال مميزة عن قبول الواجهة. لا تتضمن التسليمات صور اختبار.

إعادة الإنتاج على الحزمة الأصلية: F11-01 وF11-02 وF15-02 من الواجهة؛ F13-01/02/03 وF14-01 وF18-01 باختبارات موجهة في المتصفح؛ F11-03 وF12-01/02/03 وF16-01 في فحص الإجراءات الأصلي. لا أزعم إعادة إنتاج حادثة فقد آخر 34 تحويلًا و68 قيدًا أو فقد المرفق القديم. فشل توقعات الإصلاح في ملفات baseline يعني إعادة ظهور العيب الأصلي، وليس قبولًا له. ملفات الأدلة والسكربتات داخل `evidence/repairs-f11-f18` و`scripts/f11-f18*`.

## F17 — المرفق والنسخة الاحتياطية

التقرير يثبت وجود بيانات وصفية لـ`qa-attachment.txt` مع غياب محتواه آنذاك. ZIP المرفق لا يحتوي قاعدة تلك الشركة أو IndexedDB الخاص بمرفقات ملف المتصفح، لذلك **لم يُحسم أين ومتى فُقد المحتوى** ولم يُنسب تلقائيًا إلى F15-01. لم يُحذف السجل القديم لتمرير الاختبار ولم تُعطّل حماية رفض النسخة الناقصة.

اختبار سليم منفصل من الواجهة: رفع ملف بمحتوى معلوم، التحقق من البيانات الوصفية وBlob، تنزيل النسخة الكاملة مع bytes، إضافة سجل لاحق، ثم **تنفيذ الاستعادة فعليًا** مع النسخة الوقائية الافتراضية؛ اختفى السجل اللاحق وتطابقت القيود الخام وعاد محتوى المرفق حرفيًا. المسار السليم ناجح، لكن عائق المرفق التاريخي يظل مفتوحًا ويتطلب مخزنه الأصلي أو نسخة تحتوي bytes الصحيحة.

## البناء والتحقق والتسليم

`npm run build` وبناء الخادم نجحا، و`npx cap copy android` حدّث أصول التطبيق من البناء. آخر `npm run verify` اجتاز 79/79 اختبارات المصدر و7/8 اختبارات المتصفح، لكنه **انتهى بفشل** `party-controls-browser-smoke.py`: زمن فتح «سند قبض» 1880.3ms يتجاوز حد الاختبار الأصلي. لم تُعدّل الحدود؛ بقي فشل زمني أيضًا في إعادة منفردة سابقة، رغم نجاح إعادة سابقة أخرى. لذلك التحقق الشامل غير مجتاز، ولا تكفي سلامة النتائج المالية لاعتماد النسخة. سجل التحقق الكامل مرفق داخل ZIP.

قورنت ملفات سكربتات الاختبارات الأصلية الـ170 مع ZIP: لا تعديل ولا فقد، ولا تغيير لتوقعاتها. الملفات المجمعة ونسخة أصول Android ناتجة عن البناء وCapacitor، ولم يُعدل dist يدويًا. لم يُبنَ APK/AAB ولم يُجرَ قبول على جهاز Android فعلي. بعض سياقات القبول التي تمنع ServiceWorker سجلت خطأ PWA `undefined.update`؛ هذا خارج بنود الإصلاح ولم يُحسم خارج سياق الاختبار.

ZIP كامل يحتوي المصدر، البناء، مشروع Android، اختبارات الإصلاح والأدلة الرقمية، بدون node_modules أو ملفات شركة اختبار خام أو صور أدلة جديدة. لتشغيل اختبارات القبول الجديدة يلزم Python وPlaywright وChromium؛ يحدد `CHROMIUM_PATH` مسار المتصفح. اختبارات النسخة الأصلية تستخدم `BASELINE_APP` لإعادة تشغيل bundle الأصلي؛ لا تدخل في مصفوفة الاختبارات القديمة ولا تستبدلها.
